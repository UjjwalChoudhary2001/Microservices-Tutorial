1. Why do we inject an Interface in the Controller/Service?

Suppose we have:

public interface QuestionService {
    List<Question> getQuestions();
}

Implementation:

@Service
public class QuestionServiceImpl implements QuestionService {

    @Override
    public List<Question> getQuestions() {
        // implementation
    }
}

In the controller:

private QuestionService questionService;

public QuestionController(QuestionService questionService) {
    this.questionService = questionService;
}
Important point

QuestionService is an interface, so:

QuestionService questionService;

does not create an interface object.

It creates a reference variable.

Spring creates the actual implementation object:

QuestionServiceImpl obj = new QuestionServiceImpl();

and conceptually connects it:

QuestionService questionService = obj;

So:

QuestionService reference
        ↓
QuestionServiceImpl object

This is Dependency Injection.

Why use the interface?

Because the controller depends on the contract, not the implementation.

Controller
    ↓
QuestionService (interface)
    ↑
QuestionServiceImpl

This gives loose coupling.

Constructor injection
public QuestionController(QuestionService questionService) {
    this.questionService = questionService;
}

Spring automatically finds the appropriate implementation and injects it.

You can also use:

@Autowired
private QuestionService questionService;

but constructor injection is generally preferred.

2. Why does QuestionRepository work without @Repository?

You have:

public interface QuestionRepository
        extends JpaRepository<Question, Long> {

    List<Question> findByQuizId(long quizId);
}

You might wonder:

"There is no @Repository, so how is a bean created?"

Answer: Spring Data JPA

More precisely, Spring Data JPA, not JPA itself, handles this.

Spring Data JPA sees:

extends JpaRepository<Question, Long>

and creates a repository implementation at runtime.

Conceptually:

class GeneratedQuestionRepository
        implements QuestionRepository {
    
    // implementations generated by Spring Data JPA
}

Then Spring creates a bean from this generated implementation.

So your service can do:

@Service
public class QuestionServiceImpl {

    private final QuestionRepository questionRepository;

    public QuestionServiceImpl(QuestionRepository questionRepository) {
        this.questionRepository = questionRepository;
    }
}

Spring finds the generated repository bean and injects it.

What about findByQuizId()?

You don't implement it yourself:

List<Question> findByQuizId(long quizId);

Spring Data JPA understands the method name and generates the required query/implementation.

⭐ Remember this
@Service
QuestionServiceImpl
        ↓
Spring creates bean directly

Whereas:

QuestionRepository extends JpaRepository
        ↓
Spring Data JPA creates implementation
        ↓
Spring creates bean
One-line revision

For normal classes, annotations like @Service tell Spring to create/manage the bean; for Spring Data JPA repository interfaces, Spring Data JPA automatically creates the implementation and registers the repository as a bean.
